# net/（マルチプレイ）

友達と遊ぶための通信。PeerJS（WebRTC）でブラウザ同士を直接つなぐ。部屋を開いた人（ホスト）には部屋コードが出て、友達はそれを入れて参加する。**世界の正しい状態はホストのブラウザが持つ**。PeerJS の無料サーバー（0.peerjs.com）はつなぐ瞬間だけ使い、ゲームのデータは通らない。

> **このフォルダのファイルを追加・削除・変更したら、この CLAUDE.md の内容も合わせて見直し、必要なら書き換えること。**
> ルートの `CLAUDE.md` のフォルダ構成の表・開発方針に関わる変更なら、そちらも直す。

## ファイル

| ファイル | 中身 |
|---|---|
| `protocol.ts` | 送り合うメッセージの形。参加者→ホスト（`GuestMsg`）、ホスト→参加者（`HostMsg`）、つながりの決まりごと（`ServerMsg`：入れた・入れない・部屋を閉じた）、自分の様子（`PoseMsg`）、動いている物の位置（`Motion`。海図に載せた島の分は `isles`） |
| `link.ts` | 部屋のつながり。ホストの部屋（`HostLink`。部屋コードから決まる PeerJS の ID で待ち、参加者に番号を付ける）と、参加者のつながり（`GuestLink`）。部屋コードの形をそろえる `cleanCode()` |
| `multiplayer.ts` | マルチの進め方（`Multiplayer`）。役割（`solo`・`host`・`guest`）、頼みの送り先（`request()`）、届いたメッセージの処理、様子・動き・時刻を送る間隔。場所ごとの物理の担当（`sims`。ホストがみんなのいる場所から決めて配る。担当は自分のいる場所の動きを送り、ほかの人は自分が担当の場所の動きを受け取っても使わない）。ゲームの世界とは `WorldHooks`（`main.ts` が渡す）だけでつながる |

## 流れ

- **部屋を開く**：ホストはワールドを読み込んでから `host()`。部屋コード（5文字）を決めて PeerJS に名乗る（ほかの部屋と重なったら作り直す）。参加者が来たら（`hello`）、`hooks.shared()` の世界のまるごとの状態と、部屋にいる人を送る
- **参加する**：`join(部屋コード)` で世界を受け取り、`main.ts` が組み上げてから `ready()`。それまでに届いたメッセージはためておく。世界を受け取る前に届いたコマンドは、受け取る状態に入っているので捨てる
- **頼み**：参加者は手元で `authorize` して通りそうなら番号 `n` を付けてホストへ送る。ホストは確かめてコマンドを全員に配ってから自分でも適用する（`publish`）。だめなら頼んだ人にだけ `reject` を返し、参加者は `hooks.undo()` で先に減らした物を戻す
- **世界の頼み**（`by` が `null`。時間で埋まる穴など）はホストのものだけを使う。参加者の `request(req, null)` は何もしない
- **配るもの**：自分の様子は毎秒15回（ホストがほかの人へ中継する）、落とし物・倒れた木の動きは毎秒10回（その場所の物理の担当から。参加者が担当ならホストが中継する）、時刻は2秒ごと（ホストから）
- 人が抜けたら、ホストは `hooks.left()` で、その人が乗っていた船を降ろす。ホストがいなくなったら、参加者は自分だけの状態をセーブしてタイトルへ戻る

## 書くときの決まり

- 共有ワールドの変更はワールドコマンドだけで配る。新しい共有の物を足すときに、ここへ専用のメッセージを足さない（時刻や物理の位置のように、毎フレーム変わる物だけは例外）
- 送る中身は小さく保つ。小数は丸める（`round()`）。毎フレーム送らず、間隔を決めて送る
- 送るのは JSON の文字列（PeerJS の `raw`）。WebRTC は約16KBを超える1通が届かないことがあるので、長いものは `link.ts` の `Wire` が分けて送り、受け取る側でつなぎ直す（PeerJS の `json` は16KBを超えるとエラーになるので使わない）
- 届いた値はそのまま信じず、形を確かめる（名前は `cleanName()`、見た目は `toLook()`、頼みは各クラスの `authorize()`）
- メッセージの形を変えたら、古いページとは遊べなくなる。ホストと参加者は同じ版のページを開く（GitHub Pages に上げたら、全員読み込み直す）
- 学校や会社の回線など、直接つながれないネットワークでは、PeerJS が用意している中継（TURN）を通る。遅くなったりつながらなかったりするときは、自前の TURN サーバーを `Peer` の `config.iceServers` に足す
